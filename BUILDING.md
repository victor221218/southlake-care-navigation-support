# Build the desktop test app

> **Current release: 2.16.0 personal document assistant.** Start with README.md and WINDOWS-DEVELOPMENT.md for the current Windows workflow and Mac test packages. The notes below describe earlier experiments.

Testers use the installer or an app bundle; they do not need these tools.

The application implements the published Sign in with ChatGPT protocol independently. It does not include OpenAI's separately licensed demonstration DevKit. A working app build does not establish the user's plan eligibility or OpenAI approval for a private app.

Developer prerequisites: Node.js 24, pnpm 11, and Python 3. Install the pinned dependencies with `pnpm install --frozen-lockfile`, then run `pnpm test` and `pnpm build`. Run `node scripts/package.mjs` to build `release/app.asar` and collect third-party notices.

The bundled Vosk English model is Apache-2.0. Its upstream archive URL and SHA-256 are in `assets/voice-model-source.json`. The synthetic voice-check WAV says “Find home support in Aurora.” No patient records or credentials are included in source or distribution packages.

Run `node scripts/check-voice-engine.mjs` to exercise the actual bundled WASM engine, acoustic model and sample WAV without a microphone or browser UI. This uses a JavaScript VM harness and Vosk’s actual `downloadAndExtract` function to unpack the shipped archive, then verifies recognition. This archive check is also part of `pnpm test`. Do not replace it with direct filesystem injection: that missed the missing-directory-entry fault in version 1.2.0.

The archive must include `model/` and all parent directories before the regular model files. `scripts/repack-voice-model.py` creates reproducible gzip/USTAR output with those entries while preserving file contents. After changing the archive, update its packaged SHA-256/revision in `assets/voice-model-source.json`; the revision is used in the speech URL to avoid reusing an older failed cache entry.

For a native Windows smoke check, run the normal build/package steps, `node scripts/prepare-voice-smoke.mjs`, then `python scripts/prepare-windows.py --voice-smoke`. Launch `.runtime/voice-smoke-<version>/Southlake Hive Voice Test.exe` in a normal Windows desktop session. It runs hidden with an isolated data folder and test-only preload/page, exercises the shipping main process/protocol/CSP/worker on fresh and second loads, writes `voice-smoke-result.json`, then quits. It never signs in or requests microphone access. This bootstrap is not included in the shipping ASAR. Version 1.2.1 passed both native recognition checks.

For the assistant acceptance check, run the normal build/package steps, `node scripts/prepare-assistant-smoke.mjs`, then `python scripts/prepare-windows.py --assistant-smoke`. Launch `.runtime/assistant-smoke-<version>/Southlake Hive Assistant Test.exe`. It runs the production main, renderer and preload with an isolated empty database. It sends the actual client phrase through the UI, opens recommendation cards, edits comments, checks alternatives, then relaunches the real executable to verify selected context and the final comment. Closing the app immediately after typing exercises the production save-before-close handshake. It writes `assistant-smoke-result.json`. Its data is synthetic and private to the workspace test folder; no microphone or sign-in is opened. It briefly shows its own test window without focus when taking visual QA snapshots. Test scripts, profiles and bootstrap are excluded from shipping ASARs.

An optional developer-only `--check-existing-connection` flag on the preparation script permits two public read-only AI prompts using Hive's own existing native connection. It does not import Codex credentials, start authorization, refresh tokens, write the credential vault or read personal outcome history. Missing, expiring or undecryptable credentials stop that optional check. Reports contain structural event counts and public-contact checks, not tokens or raw AI output. Version 1.3.0 passed the isolated first-use checks; its optional live check could not decrypt existing credentials in this environment, so live inference is not verified.

`src/local-guide.mjs` routes clear service-type/community requests locally. `src/feedback.mjs` resolves organization/program compounds before generic brand names, recognizes ordinary refusals and separates provider refusal from patient choice. Explicit named programs override selected-service references. Unknown named providers cannot silently become the previous selection. `src/library-store.mjs` stores requests, outcomes and explicit program comments separately. Hypothetical/private/future wording does not manufacture personal outcomes. Incomplete provider references can be resolved by a card click. Full conversations are not stored; attributable service-feedback excerpts are deliberately retained as service comments.

The model can use the desktop-only `capture_feedback` tool for broader wording. The host requires an exact quote from the current user message and an unambiguous provider reference, validates fields, and applies the same library/outcome rules. It cannot take evidence from a provider website or an assistant suggestion. Direct legacy write tools still require a review confirmation. Memory writes are acknowledged even if the final AI explanation is empty or interrupted.

Migration `0001_conversation_library` preserves older outcomes, adds their optional verbal satisfaction field and creates owner-scoped library tables. Same provider/request updates use one outcome ID and optimistic versions; repeated identical feedback does not increment the denominator. New conversations reset active context, not the database. Explicit new attempts get separate request IDs. The library always reads current outcome values, including manual edits/retractions. Happy/unhappy/mixed feedback can affect the satisfaction component without inventing numeric ratings; an explicit numeric rating takes precedence when both are present.

Migration `0002_service_workspace` adds program-scoped comments, selected service and the active workspace pointer. Comment edits use IDs/versions and account checks. Autosave persists notes without manufacturing outcomes; explicit submission or leaving the editor can interpret clear result wording. General library comments stay as notes. Auto-captured comments can be tied to outcome records and are excluded when those records are retracted. The renderer clears comment drafts when switching accounts/workspaces.

SQLite work is serialized with AsyncLocalStorage-aware nested transactions. A local feedback turn persists one atomic database snapshot and emits saved events only after persistence succeeds. File writes and renames retry short Windows sharing violations; they never delete the existing database first. The production close handshake flushes note editors and pending disk writes before closing. Sign-in no longer waits on model discovery. Local cards and comments need no AI request; broader AI inference has a bounded wait and a source-labeled local fallback where possible.

`src/responses.mjs` assembles completed text, refusal and function-call lifecycle events and waits for `response.completed`. Sparse terminal snapshots cannot discard streamed output. Empty AI answers get one tool-free repair before any source-labeled directory fallback. Partial or failed streams are not accepted as completed answers. The renderer no longer invokes speech synthesis; voice is input only.

`scripts/voice-assets.mjs` extracts the pinned Vosk worker into a static `voice-worker.js`, adds progress/final-result signals, and fails the build if that dependency format changes. The worker alone receives the dynamic-compilation permission needed by Embind. The renderer keeps its stricter CSP; sandboxing and context isolation remain enabled. Speech errors, cancellation and a one-minute loading timeout terminate unsuccessful workers and allow retry.

Added services remain JSON payloads in the existing `hive_custom_services` table. New entries start with payload version 1. Edits retain IDs and require the current version, including legacy entries whose absent version is treated as 1. No migration moves records between accounts. Public source URLs may retain provider query parameters, such as a healthline program ID.

For the cross-platform ZIP scripts, obtain the official Electron archives for the pinned version in `package.json`, verify them against Electron's published SHASUMS256.txt, and create `.runtime/runtimes.json` as an array of objects with `platform` (`win32` or `darwin`), `arch` (`x64` or `arm64`), and the absolute archive `path`. Run `python scripts/distribute.py` to produce the Windows portable and two Mac test ZIPs in the workspace outputs folder. Use `--mac-only` to leave Windows artifacts unchanged, or `--platform Mac-Apple-Silicon` / `--platform Mac-Intel` for one chip.

Mac package revision `mac-2` removes Electron's starter ASAR, replaces the stale `ElectronAsarIntegrity` metadata with the shipping ASAR header hash, adds the Hive ICNS icon and preserves all untouched nested runtime code and framework symlinks. The ICNS image payloads are unchanged PNG representations from `assets/hive.ico`. `scripts/mac_package.py` checks the ZIP CRC, symlink resolution, executable modes, architecture, app version and matching ASAR. Verification is written to `Southlake-Hive-Mac-Verification.json`. These checks do not execute macOS code.

The Mac kit includes `Install Southlake Hive.command`, matching minimal microphone/JIT entitlements and a recipient checklist. The Bash 3.2-compatible installer checks the OS/chip and ASAR SHA-256, uses `ditto` to stage a per-user app copy, ad-hoc signs only the modified outer app and deep-verifies the bundle before installation. Nested upstream code is untouched. An existing installation is moved to a backup; the separate user-data folder is never moved or erased. There are no network downloads or quarantine/Gatekeeper modifications. Developer ID signing, notarization and native launch/microphone/Keychain verification remain release tasks. A local ad-hoc signature does not certify the publisher or establish notarization. See Electron's official signing guidance: https://www.electronjs.org/docs/latest/tutorial/code-signing .

For Windows Setup.exe, use the 64-bit edition of Inno Setup 7.1.1 from the official publisher. The compiler can be installed in portable mode (`/PORTABLE=1 /CURRENTUSER /NOICONS /DIR="<build-tools-folder>"`). Run `python scripts/prepare-windows.py`, then `ISCC scripts/windows-installer.iss`. The result is `release/setup/Southlake-Hive-Setup.exe`. The normal installer creates a per-user installation and shortcuts; uninstalling retains service-history files in the separate app-data folder. No elevated privileges are required.

For a packaging-only check that does not create shortcuts or uninstall registration, run the same installer with `/PORTABLE=1 /DIR="<empty-test-folder>" /VERYSILENT /SUPPRESSMSGBOXES /NORESTART`. This checks file extraction; it does not test authentication or the desktop UI. Do not use disabled Chromium sandbox flags to work around a restricted build environment.

The Windows app and installer have not been code-signed. Real account authorization and ChatGPT inference must be verified with a consenting tester. The automated tests simulate the identity provider and model responses; they do not claim live OpenAI interoperability.

Inno Setup is by Jordan Russell and Martijn Laan: https://jrsoftware.org/ . The installer is compiled with the unmodified official toolchain.
